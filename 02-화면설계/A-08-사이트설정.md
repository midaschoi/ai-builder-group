## 1. 이 화면이 왜 생겼나

기획서·IA·PRD 는 8/11 에 작성됐고, 이 요구사항은 **8/12 미팅에서 나왔다.** 그래서 A-01~A-07 어디에도 없다.

> **클라이언트 (04:22)**
> "플러그 같은 경우에는 그냥 임의로 계정 하나 만드신 다음에 폼 연동해 놓으시고,
> 나중에 저희가 바꿀 수 있게끔만 **관리자 페이지에서 링크만 딱 바꾸면 렌더링 되게끔만** 해 주시면
> 그거는 저희가 받아서 나중에 만들게요."

> **클라이언트 (05:01)**
> "네이버랑 **구글 서치 콘솔** 이런 것들은 그냥 한 번 등록하면 되는 거라서 그렇게 해 주시면 되고
> 제가 제 이메일 계정은 두 개 전달 드릴게요."

핵심은 **"우리가 나중에 바꾼다"** 이다. 지금까지 이 값들은 전부 환경변수(`.env.local`)에 있었고,
그러면 값을 바꿀 때마다 Vercel 설정에 들어가 재배포해야 한다 — **클라이언트가 스스로 못 바꾼다.**
요구사항이 정확히 그 지점이라 DB 로 옮기고 관리 화면을 붙인다.

### 화면 수에 대한 판정

PRD §3.1 의 기준선은 17화면이고, 이 화면은 18번째다.
다만 **미팅에서 클라이언트가 직접 요청한 것**이므로 "범위 밖 → 만들지 않음"이 아니라
**범위 변경 승인 대상**이다. 백로그 §1.3 에 기록했다.

> 💡 대안으로 "빌더 관리(A-06) 안에 탭으로 넣기"도 검토했으나 채택하지 않았다.
> A-06 은 계정 관리 화면이고 사이트 전역 연동 설정은 성격이 다르다.
> 무엇보다 **A-06 은 P1 이고 이 화면은 P0** 라서 순서가 뒤집힌다.

## 3. 항목

| 항목 | DB 컬럼 | 검증 | 비우면 |
|---|---|---|---|
| 문의 폼 주소 | `pluug_form_url` | `http(s)://` 로 파싱되는 URL | 환경변수 `NEXT_PUBLIC_PLUUG_FORM_URL` 로 되돌아감 |
| 구글 서치 콘솔 | `google_site_verification` | 없음 (태그 통째로 허용) | 확인 태그를 넣지 않음 |
| 네이버 서치어드바이저 | `naver_site_verification` | 없음 | 〃 |
| GA4 측정 ID | `ga4_measurement_id` | `^G-[A-Z0-9]{4,}$` | **스크립트를 아예 로드하지 않음** |
| 채널톡 플러그인 키 | `channel_plugin_key` | 없음 | 환경변수로 되돌아감 |

### 3.1 태그를 통째로 붙여넣어도 받는다

서치 콘솔이 주는 것은 이런 형태다:

```html
<meta name="google-site-verification" content="AbCdEf123..." />
```

사람들은 이걸 **통째로 복사한다.** 그대로 저장하면 태그 안에 태그가 들어가 소유권 확인이 실패한다.
저장 시 `content="..."` 를 정규식으로 뽑고, 못 찾으면 입력값을 그대로 쓴다.

> 값만 넣으라고 안내문을 쓰는 것보다, 둘 다 받는 편이 지원 요청을 줄인다.

### 3.2 GA4 는 값이 있을 때만 로드한다

빈 gtag 를 넣어두면 네트워크만 쓰고 데이터는 안 쌓인다.
`ga4_measurement_id` 가 비면 `<Script>` 자체를 렌더하지 않는다.

이벤트 래퍼는 **`window.track` 하나뿐**이다 (TR-03 — 개별 호출 산재 금지).
`components/SiteFx.tsx` 가 콘솔 출력 스텁을 `??=` 로 넣고,
`components/Analytics.tsx` 가 측정 ID 가 있을 때 실제 전송 구현으로 덮는다.
`??=` 라서 마운트 순서가 어느 쪽이든 실제 전송이 남는다.

## 4. 공개 웹에 반영되는 경로

```
관리자 저장
   │
   ├─ site_settings 1행 update
   ├─ updateTag('site-settings')     ← 캐시를 즉시 깬다
   └─ revalidatePath('/', 'layout')
        │
        ▼
   ┌─────────────────────────────────────────────────────────┐
   │ lib/settings.ts  getSiteSettings()  (unstable_cache)    │
   └─────────────────────────────────────────────────────────┘
        │
        ├─ app/layout.tsx  generateMetadata()  → 구글·네이버 확인 태그
        ├─ app/layout.tsx  <Analytics>         → GA4
        ├─ app/layout.tsx  <ChannelTalk>       → 채널톡
        └─ app/contact/page.tsx                → pluug 폼 주소
```

### ⚠ 캐시가 이 설계의 핵심이다

공개 웹 11장은 **정적 생성(SSG)** 이다. 설정을 매 요청 DB 에서 읽으면 전부 동적 렌더로 바뀌어
첫 응답이 느려진다. 그래서 태그 캐시로 감싸고 저장할 때만 깬다.

빌드 결과로 확인한다 — 공개 라우트가 `○ (Static)` 이고 `/admin/*` 만 `ƒ (Dynamic)` 이어야 한다.

| | 값 |
|---|---|
| 캐시 태그 | `site-settings` |
| 안전망 revalidate | 300초 (태그 갱신을 놓쳐도 5분이면 따라잡는다) |
| 즉시 반영 | `updateTag` — ⚠ `revalidateTag` 가 아니다. Next 16 에서 시그니처가 바뀌었고, 서버 액션에서 "저장한 값을 곧바로 다시 읽는" 용도는 `updateTag` 다 |

## 5. 권한

| | 관리자 | 빌더 |
|---|---|---|
| 화면 진입 | ⭕ | **403** |
| 저장 | ⭕ | ❌ (서버 액션이 `requireAdmin()` 으로 다시 막는다) |
| RLS | `site_settings_write` = `is_admin()` | — |

세 겹이다 — 메뉴 숨김(편의) · 화면 403(서버) · RLS(DB).
사이트 전역 설정은 빌더가 건드릴 수 있으면 안 된다.

> ⚠ `site_settings` 는 **누구나 읽을 수 있다**(공개 웹이 비로그인 상태로 읽어야 하므로).
> 그래서 **비밀이 아닌 값만 넣는다.** GA4 측정 ID · 서치콘솔 코드 · pluug 주소는 모두
> 최종적으로 HTML 에 노출되는 공개 값이다. **API 시크릿을 이 표에 넣지 말 것.**

## 6. 검수 항목

- [ ] 빌더 계정으로 `/admin/settings` 접근 → **403**
- [ ] 빌더가 저장을 서버로 직접 요청 → 거부
- [ ] pluug 주소를 바꾸고 저장 → **재배포 없이** `/contact` 폼이 바뀌는가 ★ 미팅 요구사항의 핵심
- [ ] 서치콘솔 태그를 **통째로** 붙여넣고 저장 → `<head>` 에 `content` 값만 들어가는가
- [ ] 구글·네이버 확인 코드를 넣고 배포 → 각 서치 콘솔에서 소유권 확인이 통과하는가
- [ ] GA4 측정 ID 를 비운 상태 → gtag 스크립트가 **아예 요청되지 않는가** (네트워크 탭)
- [ ] GA4 측정 ID 를 넣은 상태 → `[data-track]` 클릭이 DebugView 에 뜨는가 (TR-02)
- [ ] 잘못된 GA4 형식(`UA-123`) → 저장이 거부되는가
- [ ] 저장 후 빌드 결과에서 공개 라우트가 여전히 `○ (Static)` 인가 ★ 캐시가 깨지지 않았는지
- [ ] 마이그레이션 전(테이블 없음) 상태에서도 공개 웹이 정상 동작하는가
