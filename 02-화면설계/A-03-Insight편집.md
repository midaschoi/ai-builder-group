
> 반려 사유를 **편집 화면 안에서** 보여준다. 목록에만 있으면 고치는 동안 안 보인다 (FR-A07-04).

## 상단 바 — 버튼은 역할·상태에 따라 달라진다

| 현재 상태 | 빌더에게 보이는 버튼 | 관리자에게 보이는 버튼 |
|---|---|---|
| 신규 / `draft` | `[임시저장]` `[제출하기]` | `[임시저장]` `[발행하기]` |
| `pending` | (버튼 없음 · 읽기 전용) `제출 후에는 수정할 수 없습니다` | `[반려]` `[발행하기]` |
| `rejected` | `[임시저장]` `[다시 제출]` | `[임시저장]` `[발행하기]` |
| `published` | (읽기 전용) | `[수정 저장]` `[보관하기]` |
| `archived` | (읽기 전용) | `[다시 발행]` |

- ⛔ **빌더에게 `[발행하기]` 버튼을 렌더하지 않는다.** 그리고 서버에서도 거부한다 —
  빌더의 `published` 직행 시도는 **403** 이 인수 조건이다 (DR-06).
- 저장 중에는 버튼 비활성 + 스피너. 이중 저장으로 슬러그 중복이 나는 것을 막는다.

## Tiptap 툴바 — **h1 차단이 핵심**

| 그룹 | 항목 |
|---|---|
| 제목 | **H2 · H3 만** |
| 강조 | 굵게 · 기울임 · 취소선 |
| 링크 | 삽입 · 해제 (외부 링크는 `rel="nofollow noopener"` 자동) |
| 목록 | 글머리 · 번호 |
| 블록 | 인용 · 코드블록 · 구분선 |
| 미디어 | 이미지 삽입 (업로드 → Storage URL) |

### ⛔ H1 을 막는 두 겹 (FR-A03-02)

```
1겹 — 툴바에 H1 버튼이 없다
2겹 — 저장 시 서버에서 본문의 <h1>을 <h2>로 강등한다
```

> 툴바에서 뺀 것만으로는 부족하다. **다른 곳에서 복사해 붙이면 h1 이 그대로 들어온다.**
> 공개 상세 페이지(P-05)는 글 제목이 h1 이므로, 본문에 h1 이 또 생기면 문서 구조가 깨진다.

### 서버 sanitize (FR-A03-03)

| 항목 | 처리 |
|---|---|
| 시점 | **저장 시 서버에서.** 클라이언트 정제는 우회 가능하므로 신뢰하지 않는다 |
| 제거 | `<script>` `<iframe>` `<style>` · `on*` 속성 · `javascript:` URL |
| 허용 태그 | h2 h3 p strong em s a ul ol li blockquote pre code img hr br |
| 저장 형태 | `insights.body_html` — **sanitize 후의 HTML** (DR §7.2) |
| 렌더 | 공개 페이지에서 `dangerouslySetInnerHTML`. 그래서 저장 시점 정제가 유일한 방어선이다 |

## 슬러그 — 실수가 가장 비싼 필드

```
┌───────────────────────────────────────┐
│ 슬러그 *                              │
│ [vibe-coding-difference            ]  │
│ /insight/vibe-coding-difference       │ ← 최종 주소를 그대로 보여준다
│ ✓ 사용 가능                           │
└───────────────────────────────────────┘
```

| 상황 | 표시 |
|---|---|
| 비어 있음 | `✗ 슬러그를 입력해 주세요` — **저장 불가** (FR-A03-04) |
| 중복 | `✗ 이미 사용 중인 슬러그입니다` — **저장 거부** |
| 규칙 위반 | `✗ 영문 소문자·숫자·하이픈만 사용할 수 있습니다` |
| 사용 가능 | `✓ 사용 가능` |

- 제목 입력 시 슬러그를 자동 제안하되, **한글 제목은 자동 변환하지 않는다.**
  한글을 로마자로 옮기면 읽을 수 없는 주소가 나온다. 비워두고 직접 입력하게 한다.
- 검사 시점: blur + 저장 시 (서버 재확인).

### 발행 후 슬러그를 바꾸면 (FR-A03-05)

```
┌────────────────────────────────────────────────────┐
│  ⚠ 발행된 글의 주소를 바꾸려고 합니다              │
│                                                    │
│   이전  /insight/vibe-coding-difference            │
│   변경  /insight/vibe-coding-outsourcing           │
│                                                    │
│   저장하면 이전 주소를 새 주소로 넘기는            │
│   301 리다이렉트를 자동으로 만듭니다.              │
│   (검색 순위와 외부 링크가 유지됩니다)             │
│                                                    │
│                     [취소]  [바꾸고 저장]          │
└────────────────────────────────────────────────────┘
```

저장 시 `redirects` 테이블에 `from_path` → `to_path` 를 자동 생성한다 (DR §7.2).
**구 URL 접근 시 301 응답**이 인수 조건이다.

## 저장 · 검증

### 필수 항목 (없으면 제출·발행 불가)

| 필드 | 임시저장 | 제출·발행 |
|---|---|---|
| 제목 | 선택 | **필수** |
| 슬러그 | 선택 | **필수** (FR-A03-04) |
| 카테고리 | 선택 | **필수** |
| 요약 | 선택 | **필수** |
| 본문 | 선택 | **필수** |
| 썸네일 | 선택 | 선택 |
| SEO 메타 | 선택 | 선택 → 미입력 시 자동 생성 (FR-A03-06) |

> 임시저장은 **아무 것도 안 채워도 된다.** 쓰다 만 글을 저장 못 하면 브라우저에 붙잡히게 된다.
> 검증은 제출·발행 시점에만 건다.

### 자동 저장

| 항목 | 값 |
|---|---|
| 주기 | 변경 후 30초 무입력 시 초안 자동 저장 |
| 표시 | 상단 바에 `저장됨 · 09:03` |
| 대상 | `draft` · `rejected` 만. `pending`·`published` 는 ⛔ |

> `published` 를 자동 저장하면 **편집 도중의 미완성 문장이 공개 사이트에 나간다.**

### 이탈 경고 (FR-A00-07)

미저장 변경이 있는 채로 나가려 하면 — 브라우저 이탈과 앱 내부 이동 **양쪽 모두** 막는다.
자세한 스펙은 `A-00-공통-관리자셸.md` §3.4.

## 발행 후 공개 반영 (FR-A03-08)

```
[발행하기] → status = published → 온디맨드 재검증 호출
                                    ├ /insight
                                    ├ /insight/[category]
                                    ├ /insight/[slug]
                                    └ /sitemap.xml
                                  → 토스트: 발행했습니다 · 공개 반영까지 최대 60초
```

인수 조건은 **공개 페이지 60초 이내 반영**이다.

> ⚠ **선행 조건** — 현재 공개 웹은 `/insight-detail` 한 장짜리 정적 페이지이고 데이터가 코드에 박혀 있다.
> `/insight/[slug]` 동적 라우트와 DB 연결이 되기 전까지 이 재검증은 **호출할 대상이 없다.**
> 관리자 단독 개발 구간에서는 상태 전이까지만 구현하고, 재검증 호출은 공개 웹 연결 작업에서 켠다.

## 이미지 업로드

| 항목 | 스펙 |
|---|---|
| 저장소 | Supabase Storage (공개 버킷) |
| 경로 | `insights/{id}/{uuid}.{ext}` |
| 제한 | jpg · png · webp / 최대 2MB |
| 초과 시 | `이미지는 2MB 이하로 올려주세요` — 자동 압축 ⛔ (품질 사고를 만든다) |
| alt | 삽입 시 **입력을 요구한다.** 비우면 장식 이미지로 간주해 `alt=""` |
| 실패 | 본문에 깨진 이미지를 넣지 않고 오류 토스트 |
| next.config | `images.remotePatterns` 에 Storage 도메인 등록 필요 (현재 비어 있음) |

## 검수 항목

- [ ] 툴바에 H1 이 없고, **h1 을 붙여넣고 저장하면 h2 로 바뀌는가** (FR-A03-02 두 겹)
- [ ] `<script>alert(1)</script>` 를 붙여넣고 저장 → 공개 렌더에서 실행되지 않는가 (FR-A03-03)
- [ ] 슬러그를 비우고 제출 → 저장이 거부되는가 (FR-A03-04)
- [ ] 이미 있는 슬러그로 저장 → 거부되는가
- [ ] 발행된 글의 슬러그 변경 → 경고가 뜨고, 저장 후 **구 URL 이 301** 인가 (FR-A03-05)
- [ ] 빌더 화면에 `[발행하기]` 가 없고, 서버 발행 요청도 **403** 인가 (DR-06)
- [ ] `pending` 상태에서 빌더가 편집할 수 없는가 (DR-07)
- [ ] 반려된 글의 사유가 편집 화면 상단에 보이는가
- [ ] 내용을 고치고 저장 없이 사이드바 메뉴 클릭 → 경고가 뜨는가
