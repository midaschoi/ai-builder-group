# A-05 Work 편집 `/admin/work/[id]`

| | |
|---|---|
| 우선순위 | **P0** |
| 접근 | 관리자 · 빌더(본인 참여분만) |
| 셸 | ⭕ 적용 · 사이드바 접은 상태 |
| 신규 작성 | `/admin/work/new` |
| 기준 문서 | 상단 바 · 저장 규칙 · 슬러그 · 이탈 경고는 **A-03 과 동일** (FR-A05-05) |

---

## A-03 과 같은 것

상단 바 버튼 구성 · 상태 머신 · 슬러그 검증과 301 자동 생성 · 자동 저장 · 이탈 경고 ·
발행 후 온디맨드 재검증 · 이미지 업로드 스펙 — **전부 A-03 을 따른다.**

## A-03 과 다른 것 — **본문이 자유 에디터가 아니다**

| | A-03 Insight | A-05 Work |
|---|---|---|
| 본문 | Tiptap 자유 편집 (`body_html`) | **문제 / 해결 / 결과 3칸 고정** |
| 작성자 | 단일 | **참여 빌더 다중 연결** |
| 이미지 | 썸네일 1장 | **히어로 + 썸네일** |

> 🔒 **3막을 컬럼으로 분리하는 이유** (DR §7.2) — 공개 상세(P-03)의 렌더 구조를 고정하기 위해서다.
> 자유 에디터로 두면 사람마다 구성이 달라지고, 9개 프로젝트를 나열했을 때 페이지마다 뼈대가 어긋난다.
> **작성자가 구조를 고민하지 않게 하는 것이 목적**이지 제약이 목적이 아니다.

## 3막 입력 (FR-A05-01)

| 칸 | DB 컬럼 | 에디터 | 안내 문구 |
|---|---|---|---|
| ① 문제 | `body_problem` | Tiptap **축소판** | 무엇이 문제였는지 |
| ② 해결 | `body_solution` | Tiptap 축소판 | 어떻게 풀었는지 |
| ③ 결과 | `body_result` | Tiptap 축소판 | 무엇이 달라졌는지 |

### Tiptap 축소판 툴바

```
│ B I │ 🔗 │ ≡ 1. │ ▭ │      ← 제목(H2·H3) · 인용 · 코드블록 없음
```

> 3막 안에 제목을 또 넣으면 공개 페이지의 섹션 제목과 중복된다. **문단·목록·이미지면 충분하다.**
> sanitize·h1 강등 규칙은 A-03 §서버 sanitize 와 동일하게 적용한다.

### ③ 결과 칸의 경고

기획서 절대 규칙 — **근거 없는 수치 금지**(C2). 입력 중 상시 노출되는 안내를 둔다:

```
⚠ "전환율 3배" 같은 수치는 출처나 측정 조건 없이 쓰지 않습니다.
```

차단하지는 않는다(자동 판정이 불가능하다). **승인 단계(A-07)에서 사람이 거른다.**

## 참여 빌더 연결 (FR-A05-02) — 이 화면의 고유 기능

```
┌─────────────────────────────────┐
│ ▸ 참여 빌더 *                   │
│ ┌─────────────────────────────┐ │
│ │ ⠿ 조쉬        [리드    ▾] ✕ │ │  ← sort = 0
│ │ ⠿ 도현        [개발    ▾] ✕ │ │  ← sort = 1
│ └─────────────────────────────┘ │
│ [+ 빌더 추가              ▾]    │
│   ┌───────────────────────────┐ │
│   │ 🔍 이름 검색              │ │
│   │ ─────────────────────────  │ │
│   │ 리아   랜딩·인터랙션      │ │
│   │ 유나   AI 서비스·에이전트 │ │
│   │ 세인   데이터·업무 자동화 │ │
│   │   (비활성 계정은 안 보임) │ │
│   └───────────────────────────┘ │
└─────────────────────────────────┘
```

| 항목 | 스펙 |
|---|---|
| 저장 | `work_builders(work_id, builder_id, role_label, sort)` |
| 역할 라벨 | 선택형 — 리드 / 기획 / 디자인 / 개발 / AI · 데이터 / 기타. `기타` 선택 시 직접 입력 |
| 순서 | 드래그로 변경 → `sort`. **공개 P-03 사이드 노출 순서가 이 순서다** |
| 최소 | 1명 이상 (제출·발행 시 검증) |
| 후보 목록 | `is_active = true` 인 빌더만. 회수된 계정은 새로 붙일 수 없다 |
| 이미 연결된 빌더 | 후보 목록에서 제외 (중복 연결 방지 — PK 가 복합키다) |
| 회수된 빌더가 이미 연결된 경우 | **연결은 유지**하고 `(비활성)` 표기. 콘텐츠는 유지한다 (PRD D4) |

> 공개 P-03 은 1차에서 **빌더 이름·역할 칩 표기까지만**이고 프로필 링크가 없다 (FR-P03-02 · Q6 미확정).
> 그러나 **데이터는 지금 정확히 쌓아둔다.** 2차에 P-11 이 열리면 이 연결이 그대로 원천이 된다.

## 슬러그 규칙 (FR-A05-03)

```
권장 형태:  <업종 또는 기술> - <프로젝트 성격>
     예시:  living-commerce-renewal
            payment-admin-console

⛔ 고객사명을 넣지 않는다 (Q7 확정 — 제외)
   ✗ iloom-renewal     ✗ nice-payment-admin
```

- 입력 필드 아래 상시 안내: `ⓘ 고객사명은 넣지 않습니다`
- 고객사명 노출은 **서면 동의를 받은 건만 사후 추가**한다 (README 절대 규칙).
- 슬러그 자동 제안 시 제목에 고객사명이 들어 있어도 **제안하지 않는다.** 비워두고 직접 입력.
- 검증·중복·301 자동 생성은 A-03 §슬러그와 동일 (FR-A05-03 = FR-A03-04·05 동일 규칙).

## 이미지 (FR-A05-04)

| 항목 | 비율 | 최대 | 필수 | 비우면 |
|---|---|---|---|---|
| 히어로 (`hero_url`) | 21:9 | 3MB | 제출·발행 시 **필수** | — |
| 썸네일 (`thumb_url`) | 16:9 | 2MB | 선택 | 히어로를 크롭해 사용 |
| OG 이미지 (`og_image_url`) | 1200×630 | 2MB | 선택 | 히어로를 사용 |

> ⚠ **현재 `public/assets/img/` 의 고객사 로고·인물 사진은 전부 서면 동의를 받지 않은 시연용 샘플**이다
> (README 절대 규칙 · CLAUDE.md §4). 관리자에서 새 이미지를 올릴 때도 동일하게 적용된다 —
> 업로드 영역에 안내를 둔다: `ⓘ 고객사 로고·인물 사진은 서면 동의 후 게재`

## 검수 항목

- [ ] 3막 중 하나만 비우고 제출 → 거부되는가
- [ ] 참여 빌더 0명으로 제출 → 거부되는가
- [ ] 빌더를 드래그로 재정렬 → `sort` 가 저장되고 공개 노출 순서와 일치하는가
- [ ] 같은 빌더를 두 번 추가할 수 없는가
- [ ] 비활성 계정이 후보 목록에 뜨지 않는가
- [ ] 이미 연결된 빌더를 A-06 에서 회수 → **연결이 끊기지 않고 `(비활성)` 로 남는가** (PRD D4)
- [ ] 슬러그 자동 제안에 고객사명이 섞이지 않는가
- [ ] 히어로만 넣고 썸네일·OG 를 비운 채 발행 → 둘 다 히어로로 대체되는가
- [ ] 빌더 계정에 `[발행하기]` 가 없고 서버도 403 인가 (DR-06)
