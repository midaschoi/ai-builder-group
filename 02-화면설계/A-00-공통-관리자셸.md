## 0. 이 문서를 먼저 읽어야 하는 이유

관리자 7화면은 **셸(사이드바 + 헤더) 안에서 콘텐츠만 갈아끼우는 구조**다.
A-01~A-07 문서는 전부 "콘텐츠 영역"만 그린다. 바깥 틀은 여기서 한 번만 정의한다.

### ⛔ 공개 웹의 인터랙션을 관리자에 가져오지 않는다

`components/SiteFx.tsx`(스크롤 리빌 · 커서 추종) · `components/fx.ts`(리본 흐름 · 플로팅 독)는
**수주용 랜딩의 설득 장치**다. 관리자는 하루에 수십 번 여는 업무 도구이므로 성격이 정반대다.

| | 공개 웹 (P-01~P-10) | 관리자 (A-01~A-07) |
|---|---|---|
| 목적 | 설득 · 전환 | 반복 작업 처리 |
| 인터랙션 | 섹션마다 다르게 (딸깍 금지) | **없음.** 상태 전환만 |
| 애니메이션 | 스크롤 리빌 · 패럴랙스 | 150ms 이하 페이드 · 토스트만 |
| 폭 | 1200px 중앙 | **화면 전체 사용** (테이블이 잘리면 안 됨) |
| 폰트 크기 | 큼 (읽히게) | 작게 (많이 보이게) |

> 관리자에 리빌 애니메이션을 붙이면 목록을 스크롤할 때마다 행이 하나씩 떠오른다. 업무 도구에서는 결함이다.

## 1. 레이아웃

### 데스크톱 (≥1280px) — 기준 해상도

```
┌──────────────┬────────────────────────────────────────────────────────────┐
│              │  [페이지 제목]                        [조쉬 ▾] ← 계정 메뉴 │ h=56
│  AI 빌더     ├────────────────────────────────────────────────────────────┤
│  그룹 관리   │                                                            │
│              │   ┌──────────────────────────────────────────────────┐     │
│ ──────────── │   │                                                  │     │
│              │   │            콘 텐 츠  영 역                       │     │
│ ▸ Insight 관리│   │        (A-01 ~ A-07 이 여기를 채운다)            │     │
│ ▸ Work 관리   │   │                                                  │     │
│ ▸ 승인 대기 ③ │   │                                                  │     │
│ ▸ 빌더 관리   │   │                                                  │     │
│              │   └──────────────────────────────────────────────────┘     │
│              │                                                            │
│ w=220px      │                                                            │
└──────────────┴────────────────────────────────────────────────────────────┘
```

### 사이드바 메뉴

| 메뉴 | 경로 | 노출 대상 | 배지 |
|---|---|---|---|
| Insight 관리 | `/admin/insight` | 관리자 · 빌더 | — |
| Work 관리 | `/admin/work` | 관리자 · 빌더 | — |
| 승인 대기 | `/admin/approvals` | **관리자만** | 대기 건수 (0건이면 배지 숨김) |
| 빌더 관리 | `/admin/builders` | **관리자만** | — |

- 빌더로 로그인하면 아래 2개는 **메뉴 자체가 렌더되지 않는다.**
  단, 숨기는 것은 편의일 뿐이고 **차단은 서버에서 한다**(PRD §2.2). URL 직접 입력 시 403.
- ⛔ **대시보드 메뉴 없음.** 로그인 후 첫 화면은 Insight 관리다 (FR-A00-03 · E10).
- 현재 메뉴는 좌측 3px 액센트 바 + 진한 배경으로 표시.

### 계정 메뉴 (우상단)

```
[조쉬 ▾]  클릭 시
       ┌──────────────────────┐
       │ 조쉬                 │
       │ josh@example.com     │
       │ [빌더]  ← 역할 배지  │
       ├──────────────────────┤
       │ 내 프로필            │ → /admin/builders (본인 것만 편집)
       │ 비밀번호 변경        │ → 이메일 링크 발송 (FR-A00-05)
       ├──────────────────────┤
       │ 로그아웃             │ (FR-A00-04)
       └──────────────────────┘
```

> IA 문서에 로그아웃·비밀번호 재설정 화면이 누락되어 있었다. **PRD D2에서 "별도 화면을 만들지 않고
> 셸 헤더 메뉴로 처리"로 확정**되었으므로 여기가 그 구현 위치다. 화면 수는 7 그대로다.

### 좁은 데스크톱 (900~1279px)

사이드바를 **184px로 좁히되 라벨은 남긴다.** 아이콘 20px + 라벨 10px 간격.

> 처음에는 1280px 미만을 전부 아이콘 레일로 접도록 적었으나, 창을 최대화하지 않은
> 노트북(1000px 안팎)이 여기 걸려 메뉴 이름이 통째로 사라졌다. 실제 사용 폭이라
> 레일은 더 좁을 때만 쓰도록 경계를 옮겼다.

### 태블릿 (768~899px)

사이드바를 **아이콘만 남긴 64px 레일**로 축소. 호버 시 라벨 툴팁(`title`).

> ⚠ 이 구간에서는 아이콘이 유일한 식별 수단이다. 메뉴를 추가할 때 아이콘을 빠뜨리면
> 레일에 빈 칸이 생겨 고를 수 없게 된다 — `nav.tsx` 의 `Item.icon` 은 선택 항목이 아니다.

### 모바일 (<768px)

- 사이드바는 햄버거 → 드로어.
- **목록(A-02·A-04·A-07)은 카드형으로 전환해 읽기까지 지원한다.**
- **편집(A-03·A-05)은 지원 대상이 아니다.** 진입 시 안내 배너:
  `이 화면은 데스크톱에서 작업해 주세요` + [목록으로]
  → Tiptap 툴바와 사이드 설정 패널을 360px에 우겨넣으면 오히려 오작동한다. 막는 편이 낫다.

## 3. 공통 컴포넌트

### 3.1 상태 배지 — **전 화면 동일**

레퍼런스의 알약형 배지(`Boosted` · `Paused` · `Pending`)를 우리 5상태로 치환한다.
**연한 배경 + 진한 같은 계열 글자**, 높이 22px · 라운드 6px · 12px/600.

| 상태 | 라벨 | 배경 | 글자 | 공개 노출 |
|---|---|---|---|---|
| `draft` | 초안 | `#EFEDE6` | `#807E74` | ❌ |
| `pending` | 승인대기 | `#FFEDD0` | `#9A5B00` | ❌ |
| `published` | 발행 | `#DBF3E4` | `#14663C` | ✅ |
| `rejected` | 반려 | `#FCE3E1` | `#A32318` | ❌ |
| `archived` | 보관 | 투명 + `1px --line` | `#807E74` | ❌ (301) |

- 색상 하나로 상태를 읽을 수 있어야 한다. 배지 외에 상태 텍스트를 중복 표기하지 않는다.
- ⚠ `published` 는 **딥그린 `#14663C`** 이다. 액센트 라임(`#D8FF3D`)과 확실히 구분되어야 한다 —
  둘 다 초록으로 읽히면 "발행됨"과 "지금 누를 수 있는 버튼"이 섞인다.
- 색만으로 구분하지 않는다. **라벨 텍스트가 항상 함께** 있으므로 색각 이상에서도 판별된다.

### 3.2 테이블

레퍼런스와 동일하게 **진한 헤더 + 흰 바탕 + 썸네일 동반 제목 셀 + 우측 관리 버튼** 구조.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 제목              카테고리   작성자   상태      수정일        관리       │ ← --ink 배경
├──────────────────────────────────────────────────────────────────────────┤   --paper 글자
│ [▩] 바이브 코딩…  방법론     조쉬    [승인대기] 08-14 3일 전 [관리 ▾]   │   h=44 상단 라운드
│ [▩] AI 에이전트…  AI·AX      유나    [발행]    08-13 4일 전 [관리 ▾]   │
└──────────────────────────────────────────────────────────────────────────┘
  Showing 1-12 of 24                                        ‹ 이전 | 다음 ›
```

| 항목 | 스펙 |
|---|---|
| 헤더 | 배경 `--ink` · 글자 `--paper` · 13px/600 · 높이 44px · 상단 모서리 12px 라운드 |
| 행 높이 | 56px (썸네일 40px 를 담는 높이). 한 화면에 12행 이상 |
| 행 호버 | `--adm-hover` 배경 + 커서 pointer |
| 행 클릭 | 편집 화면으로 이동 (행 전체가 링크. 작은 버튼을 조준하게 만들지 않는다) |
| 제목 셀 | 레퍼런스처럼 **썸네일 40×40(또는 48×27) + 제목** 한 셀. 썸네일 없으면 회색 플레이스홀더 |
| 날짜 셀 | **절대일 + 상대시간 병기** — `08-14 · 3일 전`. 레퍼런스는 상대시간만 쓰지만, 승인 업무에서는 "언제 제출됐는지"의 정확한 날짜가 필요하다 |
| `[관리 ▾]` | 레퍼런스의 `[Manage ▾]`. **점 세 개(`⋯`) 대신 텍스트 버튼**을 쓴다 — 아이콘만 두면 클릭할 수 있다는 것을 모른다 |
| `[관리 ▾]` 메뉴 | 편집 / 미리보기 / 보관 / 삭제. **보관·삭제는 관리자에게만 노출** |
| 정렬 | 기본 = 수정일 내림차순. 컬럼 헤더 클릭 정렬은 1차 범위 밖 |
| 총 건수 | 하단 좌측 `Showing 1-12 of 24` 형식 (한국어: `24건 중 1-12`) |
| 로딩 | 스켈레톤 행 5개 |
| ⛔ 체크박스 | **행 다중 선택·일괄 작업을 넣지 않는다** — 일괄 삭제는 FR-A00-06(건별 확인 모달)과 충돌한다 |

### 3.3 확인 모달 (FR-A00-06)

**파괴적 동작은 전부 이 모달을 거친다** — 삭제 · 반려 · 계정 회수.

```
┌──────────────────────────────────────────┐
│  이 글을 삭제할까요?                     │
│                                          │
│  「바이브 코딩 외주, 잘하는 곳과…」      │ ← 대상을 반드시 다시 보여준다
│                                          │
│  발행된 글입니다. 삭제하면 공개 페이지가 │ ← 결과를 먼저 말한다
│  404가 됩니다. 되돌릴 수 없습니다.       │
│                                          │
│              [취소]  [삭제]              │ ← 파괴 버튼은 오른쪽·빨강
└──────────────────────────────────────────┘
```

- ⛔ **1클릭 삭제 0건**이 인수 조건이다.
- 발행 상태 콘텐츠 삭제 시에는 위처럼 **"보관(archived)을 권합니다"** 안내를 함께 띄운다(DR-05 소프트 삭제 우선).

### 3.4 이탈 경고 (FR-A00-07)

A-03 · A-05 에서 저장하지 않은 변경이 있을 때:

- 브라우저 이탈 → `beforeunload`
- 앱 내부 이동(사이드바 클릭 등) → 자체 모달 `저장하지 않은 변경이 있습니다 [머무르기] [나가기]`

> 브라우저 기본 경고만 붙이면 **사이드바 클릭으로 나가는 경우가 안 잡힌다.** 두 경로 모두 막아야 한다.

### 3.5 토스트

우하단, 3초 자동 소멸. `저장되었습니다` · `승인했습니다` · `발행했습니다 · 공개 반영까지 최대 60초`

### 3.6 빈 상태

```
┌──────────────────────────────────┐
│   아직 등록된 글이 없습니다      │
│   [+ 새 글 작성]                 │
└──────────────────────────────────┘
```

필터 결과가 0건일 때는 문구를 바꾼다 — `조건에 맞는 글이 없습니다  [필터 초기화]`
(콘텐츠가 없는 것과 필터가 걸린 것은 다른 상황이다.)

### 3.7 폼 필드 공통 규칙

| 규칙 | 이유 |
|---|---|
| 라벨은 필드 **위**에 둔다 | 입력 중에도 라벨이 보인다 |
| 필수는 라벨 옆 `*` | placeholder 를 라벨로 쓰지 않는다 |
| 오류는 필드 **아래** 빨간 한 줄 | 상단 요약 배너만 띄우면 어느 필드인지 못 찾는다 |
| 검증 시점 | 입력 중 ❌ / **blur 시 ⭕** / 저장 시 전체 |

## 4. 디자인 톤

관리자는 브랜드 표현이 아니라 **가독성**이 기준이다. 다만 공개 웹과 남처럼 보이면 안 된다.

### 4.1 토큰 — 공개 웹 `app/style.css` 에서 가져온다

```css
/* 공개 웹이 이미 정의한 값 — 새로 만들지 않는다 */
--ink:    #0E0E0C   /* 사이드바 · 테이블 헤더 · 본문 텍스트 */
--paper:  #F4F1EA   /* 어두운 면 위의 텍스트 */
--lime:   #D8FF3D   /* 액센트 — 현재 메뉴 · 주요 버튼 */
--muted:  #807E74   /* 보조 텍스트 */
--line:   #DEDCD0   /* 경계선 */
--sans:   Pretendard Variable

/* 관리자에서 추가하는 값 — 3개뿐 */
--adm-bg:    #F7F5F0   /* 앱 배경. paper 를 한 단계 밝힌 값 */
--adm-card:  #FFFFFF   /* 카드 · 테이블 바탕 */
--adm-hover: #FAF9F5   /* 행 호버 */
```

> ⚠ **라임은 액센트 전용이다.** 현재 메뉴 · 주요 버튼(저장 · 발행 · 승인)에만 쓴다.
> 상태 배지에 라임 계열을 쓰면 `published` 초록과 섞여 색이 의미를 잃는다 (§3.1 참조).

### 4.2 레이아웃 기본값

| 항목 | 값 | 근거 |
|---|---|---|
| 앱 배경 | `--adm-bg` | 흰 카드가 떠 보이게 |
| 카드 라운드 | 12px | 레퍼런스와 동일 감도 |
| 사이드바 라운드 | 16px · 상하좌 12px 여백 | 레퍼런스처럼 **떠 있는 패널**로 처리 |
| 카드 그림자 | `0 1px 2px rgba(14,14,12,.06)` | 아주 약하게. 겹쳐 쌓지 않는다 |
| 본문 | 14px / 행간 1.5 | 많이 보이게 |
| 페이지 제목 | 24px / 700 | 레퍼런스의 `Marketplace` 위치 (상단 바 아래 본문 최상단) |
| 여백 | 카드 내부 20px · 카드 사이 16px | |
| 다크모드 | ⛔ 1차 범위 밖 | |
| 아이콘 | 라인 아이콘 1세트 (Lucide 권장). 이모지 ⛔ | |
| 애니메이션 | 150ms 페이드까지. `--hover: .15s ease` 재사용 | §0 |

### 4.3 사이드바 — 레퍼런스 구조를 그대로 가져온다

```
┌──────────────────┐
│                  │  배경        --ink
│   ▲  AI 빌더     │  로고 영역   상단 고정 · 흰 심볼
│      그룹 관리   │  라벨        --paper
│                  │
│  ▪ Insight 관리  │  ← 현재 메뉴
│  ▫ Work 관리     │     배경 --lime · 글자 --ink · 라운드 10px
│  ▫ 승인 대기 ③   │     좌우 8px 안쪽으로 들어간 pill
│  ▫ 빌더 관리     │
│                  │  비활성 메뉴  --paper 80% · 호버 시 100% + 배경 8% 흰색
│                  │  아이콘       20px 라인 · 라벨과 12px 간격
└──────────────────┘
```

> 레퍼런스는 딥틸 배경에 민트 pill 을 썼다. **우리 브랜드에서 같은 역할을 하는 조합이 잉크 + 라임**이다.
> 색만 바꾸고 구조는 그대로 쓴다.

### 4.4 레퍼런스에서 **가져오지 않은 것** — 판단 근거

레퍼런스는 데이터가 수천 건 흐르는 **마켓플레이스 운영툴**이고, 우리는 콘텐츠 수십 건짜리
**승인 워크플로**다. 흉내 내면 채울 숫자가 없어 빈 껍데기가 된다.

| 레퍼런스 요소 | 채택 | 근거 |
|---|---|---|
| 사이드바 구조 · 현재 메뉴 pill | ⭕ | §4.3 |
| 상단 우측 계정 메뉴 (아바타+이름+▾) | ⭕ | §1 계정 메뉴 — 이미 동일 |
| 진한 테이블 헤더 · 썸네일+제목 셀 | ⭕ | §3.2 |
| 상태 배지 (Boosted · Paused · Pending) | ⭕ | §3.1 — 우리 5상태로 치환 |
| 행 우측 `[Manage ▾]` 버튼 | ⭕ | §3.2 — 우리 `[⋯]` 을 이 형태로 변경 |
| `Showing 1-8 of 24` 총건수 표기 | ⭕ | §3.2 |
| 필터 행 (드롭다운 + 검색 + 우측 액션) | ⭕ | A-02 §검색·필터 |
| **상단 KPI 카드 5개** (Total Listings · Revenue …) | ❌ | **이것이 곧 대시보드다** — E10 범위 밖. 게다가 우리는 매출도 리드도 DB에 없다(DR-01). 상태 탭이 같은 정보를 더 유용하게(=필터까지) 제공한다 |
| 카테고리 요약 카드 가로 스크롤 | ❌ | 카테고리당 집계를 보여줄 지표가 없다 |
| 우측 `Reported Content` 패널 | ❌ | 신고 기능이 없다 |
| 행 체크박스 + 일괄 작업 | ❌ | 1차 범위 밖. 일괄 삭제는 확인 모달 원칙(FR-A00-06)과 충돌한다 |
| `Export CSV` | ❌ | 범위 밖 |
| 국가 · 날짜 범위 필터 | ❌ | 해당 데이터가 없다 |
| 5색 컬러 카드 | ❌ | 우리는 **색이 상태를 뜻한다.** 장식용 색을 늘리면 배지 색이 안 읽힌다 |

> 🟡 **미결 — 대시보드 화면(A-08) 신설 여부.** 위 표는 "만들지 않는다"(PRD E10) 전제로 작성했다.
> 클라이언트가 KPI 카드를 원한다면 화면 수 17 → 18 이 되므로 범위 판정이 필요하다.
> 판정 전까지 이 문서는 **대시보드 없음**으로 확정 상태를 유지한다.

## 5. 범위 밖 — 만들지 않는 것

| 항목 | 근거 |
|---|---|
| **운영 대시보드 / 통계 홈** | E10 · 백로그 §3-10. 로그인 후 첫 화면은 A-02 |
| **회원가입 화면** | FR-A01-02. 계정은 A-06에서 관리자가 발급 |
| **문의(리드) 관리 화면** | DR-01 — 리드는 pluug 가 받는다. 우리 DB에 리드 테이블 자체가 없다 |
| **FAQ 관리 화면** | 백로그 §3-4. 1차는 정적 데이터 (`app/_faq.ts`) |
| **콘텐츠(영상) 관리 화면** | PRD D1 · 백로그 §3-11. 1차는 정적 데이터 |
| **알림 센터 · 활동 로그** | 범위 밖. 요청 시 백로그로 |

**화면 수 7을 늘리는 제안은 백로그에 먼저 적고 범위 판정을 받는다.**
