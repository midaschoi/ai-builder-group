## 오류 처리 — **이 화면의 핵심**

### 메시지는 한 종류뿐이다 (FR-A01-03)

```
│  ┌──────────────────────────────────────┐  │
│  │ ⚠ 이메일 또는 비밀번호가 올바르지    │  │
│  │   않습니다.                          │  │
│  └──────────────────────────────────────┘  │
```

| 실제 원인 | 노출 메시지 |
|---|---|
| 없는 이메일 | 위 메시지 |
| 비밀번호 틀림 | 위 메시지 |
| **비활성 계정** (`is_active = false`) | **위 메시지** |

> **왜 구분하지 않는가** — "비밀번호가 틀렸습니다"라고 답하는 순간 그 이메일이 이 시스템에 등록되어 있다는
> 사실이 확인된다. 계정 목록을 만들어 주는 셈이다. 비활성 계정도 마찬가지로 구분하지 않는다.
> 회수된 빌더가 "내 계정이 정지됐구나"를 로그인 화면에서 알 필요는 없다 — 운영자가 알린다.
>
> ⚠ 개발 시 주의: Supabase Auth 는 기본적으로 원인별 메시지를 돌려준다. **그대로 노출하면 안 된다.**
> 서버에서 한 문장으로 치환한다.

### 레이트 리밋 (FR-A01-04)

| 항목 | 값 |
|---|---|
| 기준 | 🟡 동일 IP 10분당 10회 |
| 초과 시 | `잠시 후 다시 시도해 주세요.` — 남은 시간을 초 단위로 알려주지 않는다 |
| 구현 | 서버에서 판정. 클라이언트 카운트 ⛔ |

## 동작 스펙

| 상황 | 동작 |
|---|---|
| 로그인 성공 | → `/admin/insight` (FR-A00-03). `?next=` 가 있으면 그쪽 우선 |
| 이미 로그인한 채로 `/admin/login` 접근 | → `/admin/insight` 리다이렉트 (로그인 폼을 다시 보여주지 않는다) |
| 제출 중 | 버튼 비활성 + `로그인 중…`. **연타로 레이트 리밋을 자기가 소진하는 일을 막는다** |
| Enter 키 | 폼 제출 |
| 자동 초점 | 이메일 필드 |
| 자동완성 | `email` · `current-password` 속성 지정 (비밀번호 관리자 호환) |

## 비밀번호 재설정 (FR-A01-05, P1)

**별도 화면을 만들지 않는다** (PRD D2). 이메일 링크 방식이다.

```
[비밀번호를 잊으셨나요?] 클릭
        │
        ▼
┌──────────────────────────────┐
│  가입된 이메일을 입력하세요  │
│  ┌────────────────────────┐  │
│  └────────────────────────┘  │
│         [재설정 링크 받기]   │
└──────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────┐
│  입력하신 주소로 재설정 링크를 보냈습니다.   │ ← 계정이 없어도 같은 메시지
│  메일함을 확인해 주세요.                     │   (존재 여부 노출 금지)
└──────────────────────────────────────────────┘
        │
        ▼  메일의 링크 클릭 (Supabase 발송)
┌──────────────────────────────┐
│  새 비밀번호 설정            │  /admin/reset
│  새 비밀번호 *   [________]  │
│  다시 입력 *     [________]  │
│         [변경하고 로그인]    │
└──────────────────────────────┘
```

| 항목 | 스펙 |
|---|---|
| 링크 유효시간 | 1시간 |
| 비밀번호 규칙 | 최소 10자. 복잡도 강제 ⛔ (길이가 더 효과적이고, 강제 규칙은 재사용을 유발한다) |
| 완료 후 | 기존 세션 전부 만료 → 새로 로그인 |
| `/admin/reset` | 토큰이 없거나 만료면 `링크가 만료되었습니다 [다시 요청]` |

> `/admin/reset` 은 재설정 링크로만 도달하는 **경유 화면**이므로 화면 수 7에 포함하지 않는다 (PRD D2 "화면 수 불변").

## 계정 발급 직후 최초 로그인

A-06에서 임시 비밀번호로 계정을 발급한 경우, 첫 로그인 후 **비밀번호 변경을 강제**한다.

```
로그인 성공 → (must_change_password = true) → /admin/reset 로 강제 이동
```

> 임시 비밀번호가 메일함에 평문으로 남아 있는 상태를 오래 두지 않는다.
> 🟡 A-06의 발급 방식(초대 메일 / 임시 비밀번호)이 확정되면 이 절차도 함께 확정한다.
