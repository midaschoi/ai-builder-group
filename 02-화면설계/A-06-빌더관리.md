| | |
|---|---|
| 우선순위 | **P1** (단, 계정 발급·회수 FR-A06-02·03 은 **P0**) |

| 컬럼 | 비고 |
|---|---|
| 아바타 | 없으면 이름 첫 글자 이니셜 원형 |

| 최근 로그인 | 없으면 **`없음`** 을 굵게 — 발급했는데 안 들어온 계정을 찾기 위한 신호다 |

---

## ⛔ 이 화면에서 할 수 없는 것

| 못 하는 것 | 이유 |
|---|---|
| **역할을 관리자로 승격** | PRD §2.2 — **관리자 승격은 DB 직접 변경으로만.** 화면에서 관리자를 만들 수 없다 |
| 비밀번호 직접 설정·조회 | 관리자가 남의 비밀번호를 알 수 있으면 안 된다. 재설정 링크 발송만 |
| 계정 **하드 삭제** | 회수(비활성)만 제공. 삭제하면 `created_by`·`author_id` 참조가 끊긴다 |

> 역할 드롭다운을 아예 두지 않는다. 실수로 관리자를 만드는 경로 자체를 없앤다.

## 계정 발급 (FR-A06-02) — **P0**

```
[+ 계정 발급] 클릭
┌────────────────────────────────────────────────┐
│  빌더 계정 발급                                │
│                                                │
│  이름 *          [                        ]    │
│  이메일 *        [                        ]    │
│                  ⓘ 이 주소로 초대 메일이 갑니다│
│  슬러그 *        [                        ]    │
│                  /builders/____  (2차 대비)    │
│  역할 라벨       [랜딩 · 인터랙션         ]    │
│                                                │
│  발급 방식                                     │
│   ◉ 초대 메일 (권장)                           │
│     본인이 비밀번호를 직접 설정합니다          │
│   ○ 임시 비밀번호 생성                         │
│     첫 로그인 시 변경을 강제합니다             │
│                                                │
│                        [취소]  [발급하기]      │
└────────────────────────────────────────────────┘
```

| 항목 | 스펙 |
|---|---|
| 이메일 중복 | `이미 등록된 이메일입니다` — 저장 거부 |
| 슬러그 중복 | `이미 사용 중인 슬러그입니다` — 저장 거부 |
| 역할 | **항상 `builder` 로 고정 생성.** 선택지 없음 |
| 생성 결과 | Supabase Auth 사용자 + `builders` 행 (`auth_user_id` 로 연결) |
| 초대 메일 | Supabase 초대 링크. 유효기간 24시간 |
| 임시 비밀번호 | 생성 후 **모달에 한 번만 표시** + 복사 버튼. 닫으면 다시 볼 수 없다 |
| 발급 직후 로그인 | `must_change_password` → 첫 로그인 시 `/admin/reset` 강제 (A-01 참조) |
| 초대 재발송 | `[관리▾]` → `초대 메일 다시 보내기` (최근 로그인이 `없음` 인 계정용) |

> 🟡 **발급 방식은 하나로 확정하는 편이 낫다.** 두 경로를 다 유지하면 운영이 헷갈린다.
> 초대 메일을 기본으로 권장하되, 메일이 스팸으로 가는 사고를 대비해 임시 비밀번호를 남겨둔다.
> 운영 한 달 후 한쪽으로 정리한다.

## 계정 회수 (FR-A06-03) — **P0 · 이 화면에서 가장 조심할 동작**

```
[관리▾] → 계정 회수
┌──────────────────────────────────────────────────┐
│  민서 님의 계정을 회수할까요?                    │
│                                                  │
│  • 즉시 로그인이 차단됩니다                      │
│  • 진행 중인 세션도 끊깁니다                     │
│                                                  │
│  ✅ 작성한 콘텐츠는 그대로 유지됩니다            │ ← 반드시 명시
│     발행 글 4건 · 참여 프로젝트 2건              │   (실제 건수를 세어 보여준다)
│     공개 페이지는 아무 것도 바뀌지 않습니다      │
│                                                  │
│  나중에 [활성화] 로 되돌릴 수 있습니다.          │
│                                                  │
│                        [취소]  [회수하기]        │
└──────────────────────────────────────────────────┘
```

| 규칙 | 근거 |
|---|---|
| **콘텐츠 동반 삭제 금지** | PRD D4 · FR-A06-03 — 수료생이 떠났다고 발행 글이 사라지면 사이트에 구멍이 난다 |
| 세션 즉시 만료 | 비활성화만 하고 세션을 두면 이미 로그인한 창은 계속 동작한다 |
| 로그인 거부 메시지 | 일반 메시지로 통일 (FR-A01-05 · A-01 §오류 처리) |
| 참여 빌더 연결 | **끊지 않는다.** A-05 후보 목록에서만 빠지고 기존 연결은 `(비활성)` 로 남는다 |
| 되돌리기 | `[활성화]` 로 즉시 복구. 새 초대 메일 발송 필요 |
| 본인 계정 회수 | ⛔ 차단. `자기 계정은 회수할 수 없습니다` — 마지막 관리자가 잠기는 사고 방지 |

행 클릭 → 우측 패널 슬라이드 (별도 화면 ⛔ · 화면 수 7 유지)

| 필드 | 관리자 | 본인(빌더) | 타인(빌더) |
|---|---|---|---|
| 이름 · 슬러그 · 역할 라벨 · 한 줄 소개 · 아바타 | ⭕ | ⭕ | ❌ 403 |
| 이메일 | ❌ (인증 주체 — 변경 시 재인증 필요, 1차 범위 밖) | ❌ | ❌ |
| 역할 (`admin`/`builder`) | ❌ (DB 직접만) | ❌ | ❌ |
| 활성 상태 | ⭕ | ❌ | ❌ |

- **빌더는 이 화면에서 목록을 볼 수 없다.** 계정 메뉴 → `내 프로필` 로 들어오면 **본인 패널만** 열린다.
  `/admin/builders` 직접 접근 시 403 (FR-A06-05).
- 슬러그·한 줄 소개·아바타는 **2차 빌더 프로필(P-11)의 데이터 원천**이다 (FR-A06-04). 지금 정확히 채운다.

## 검수 항목

- [ ] 빌더 계정으로 `/admin/builders` 접근 → **403** (FR-A06-05)
- [ ] 빌더가 계정 메뉴 → 내 프로필 → 본인 패널만 열리고 목록이 안 보이는가
- [ ] 빌더가 남의 프로필 저장을 서버로 직접 요청 → 403
- [ ] 계정 회수 → 즉시 로그인 차단되고, **진행 중이던 세션도 끊기는가**
- [ ] 계정 회수 → **작성 글·참여 프로젝트가 공개 사이트에 그대로 남아 있는가** (PRD D4)
- [ ] 회수된 빌더가 A-05 후보 목록에서 빠지고, 기존 연결은 `(비활성)` 로 유지되는가
- [ ] 자기 계정 회수가 차단되는가
- [ ] 화면 어디에도 **역할을 관리자로 바꾸는 UI 가 없는가** (PRD §2.2)
- [ ] 임시 비밀번호가 모달 이후 다시 조회되지 않는가
