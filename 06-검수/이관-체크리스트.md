## 환경변수

배포 환경에 들어가는 값. **Secret 키는 채팅·문서·메신저에 붙여넣지 않는다.**

| 키 | 용도 | 어디서 얻나 | 비고 |
|---|---|---|---|
| `SUPABASE_URL` | 접속 주소 | Supabase → Project Settings → API | 공개돼도 무방 |
| `SUPABASE_ANON_KEY` | Publishable key | 〃 | 공개 설계된 키 |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret key | 〃 | 🔴 **RLS 를 전부 우회한다.** 서버 환경변수로만 |
| `NEXT_PUBLIC_SITE_URL` | 사이트 주소 | 도메인 확정 후 | 비우면 Vercel 도메인을 쓴다 |

> ⛔ 앞 세 개에 `NEXT_PUBLIC_` 을 붙이면 안 된다. 붙이는 순간 브라우저 번들에 실려
> RLS 만이 유일한 방어선이 된다 (PRD DR-02).

**확인 방법** — Vercel → Settings → Environment Variables 에서 Production·Preview 양쪽에 있는지.

### ⚠ 서버 리전을 Supabase 와 맞춘다

`05-서비스-nextjs/vercel.json` 이 서버 함수를 **서울(`icn1`)** 에 고정한다.

```json
{ "regions": ["icn1"] }
```

Vercel 기본값은 미국 동부(`iad1`) 다. 관리자 화면은 요청 하나에 Supabase 를 3~4번
**순서대로** 부른다 (프록시 인증 → 내 계정 조회 → 목록 카운트 → 목록 본문).
함수와 DB 가 태평양을 사이에 두고 있으면 그 왕복이 전부 더해진다 —
실측으로 **1.0~1.9초** 였고, 서울로 옮긴 뒤 **0.28~0.40초** 가 됐다.

확인: 아무 페이지나 열어 응답 헤더 `x-vercel-id` 의 **가운데** 값이 `icn1` 인지 본다
(`kix1::icn1::…` 에서 앞은 접속 지점, 가운데가 함수가 도는 곳이다).

> ⛔ **Supabase 프로젝트를 다른 리전에 새로 만들면 이 값도 같이 바꿔야 한다.**
> 안 바꾸면 관리자 화면이 다시 1초대로 느려진다. 원인이 코드에 없어서 찾기 어렵다.

## Supabase 이관 절차

1. 새 워크스페이스에 프로젝트 생성 (이름 규칙: `빌더 그룹 팀 N`)
2. SQL Editor 에 **`supabase/setup-all.sql`** 붙여넣고 실행 — 테이블·RLS·정책·초기 카테고리가 한 번에 만들어진다
3. **Authentication → URL Configuration** — Site URL 과 Redirect URLs 등록 (`supabase/EMAIL-TEMPLATES.md`)
4. 최초 관리자 계정 연결 — `supabase/migrations/0001_init.sql` §11 절차
5. 콘텐츠 이관 — 발행분이 있으면 `works` · `insights` · `work_builders` · `builders` · `faqs` · `videos` · `site_settings` 를 옮긴다
6. Storage `media` 버킷의 업로드 이미지 복사
7. Vercel 환경변수를 새 프로젝트 값으로 교체하고, **새 프로젝트 리전에 맞춰 `vercel.json` 의 `regions` 를 고친 뒤** 재배포

> ⚠ 5·6 을 빠뜨리면 화면은 뜨는데 내용이 비어 있다. **이관 후 반드시 공개 화면을 눈으로 확인한다.**

### 🔴 계정 현황 (2026-08-17 실측)

`builders` 테이블에는 11명이 있지만 **실제로 로그인되는 계정은 1개뿐이다.**

| | 이름 | 이메일 | 로그인 |
|---|---|---|---|
| 운영 관리자 | 관리자 | `builder@test.kr` | ✅ 가능 (Auth 등록 유일) |
| 빌더 ×10 | 유나 · 조쉬 · 하준 · 세인 · 민서 · 태오 · 리아 · 은채 · 도현 · 준호 | `*@sample.invalid` | ❌ **Auth 계정 없음** |

두 가지가 걸린다.

1. **관리자가 `builder@test.kr` 하나뿐이고 테스트 주소다.** 이 계정을 잃으면 관리자 화면에
   들어갈 방법이 없다. 실제 운영 주소로 교체하고, **관리자를 2명 이상** 두는 편이 안전하다.
2. **빌더 10명은 화면에 이름만 있고 아무도 못 들어온다.** 목록·상세에는 보이지만
   본인 글을 쓰거나 프로필을 고칠 수 없다. 조원 명단(이름·이메일)을 받으면 실제 계정으로 교체한다.

> 이 상태로는 "시연물"이지 "팀이 쓰는 도구"가 아니다. 명단 한 장이면 풀리는 항목이다.
