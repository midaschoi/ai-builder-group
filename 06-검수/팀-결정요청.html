팀 결정 6건

개발은 사실상 끝났습니다. 지금 릴리스를 막고 있는 것은 코드가 아니라 결정입니다. 한 번의 회의로 6건을 정하면 나머지가 전부 병렬로 풀립니다.

대상 AI 빌더 그룹 랜딩·관리자 플랫폼 읽는 사람 팀 내부 작성 2026-08-17

왜 지금인가

릴리스 게이트 8개 중 코드로 막힌 것은 사실상 없습니다. 남은 것은 전부 "무엇을 고를지"를 정해야 진행되는 항목입니다.

하나씩 순서대로 물어보면 몇 주가 걸립니다. 한 번에 정하면 며칠입니다. 아래 6건은 클라이언트 없이 팀 안에서 정할 수 있는 것만 모았습니다. 클라이언트에게 받아야 하는 5건은 별도 문서로 나갑니다.

한눈에

#결정할 것막고 있는 것
1저장소를 비공개로 돌릴지🔴 지금 위험이 진행 중
2운영 관리자 계정🔴 잃으면 복구 불가
3CTA 정리 방향 (A·B·C)게이트 G1
4모바일 성능 기준게이트 G4
5조원 명단완성도 — 지금은 아무도 로그인 못 함
6범위 변경 문서화기획서와 실제가 어긋남

추가로 반응형 육안 확인(게이트 G3)이 남아 있습니다. 결정이 아니라 작업이라 맨 아래에 따로 적었습니다.

결정 항목

01 저장소를 비공개로 돌릴까요? 지금 위험 진행 중

midaschoi/ai-builder-group 이 공개(PUBLIC) 상태입니다. 그 안에 시연용 이미지 69개 — 카카오 · 신한 · 크래프톤 로고와 인물 아바타 — 가 함께 올라가 있습니다. README에 "서면 동의를 받지 않은 샘플"로 명시된 것들입니다.

다른 항목은 늦어도 품질 문제지만, 이건 성격이 다릅니다. 지금 이 순간에도 인터넷의 누구나 볼 수 있습니다. 비공개 전환은 1분이면 되고 언제든 되돌릴 수 있습니다.

  • 비공개로 전환 — 이미지 교체 후 다시 공개. 가장 안전합니다
  • 공개 유지 — 대신 이미지 교체를 최우선으로 올립니다
참고
비공개로 바꾸면 지금 공유 중인 문서 링크(htmlpreview)도 함께 막힙니다. 그 경우 HTML 파일을 첨부해서 돌리면 됩니다
02 운영 관리자 계정을 무엇으로 할까요? 잃으면 복구 불가

지금 관리자 화면에 들어갈 수 있는 계정은 builder@test.kr 하나뿐이고, 테스트용 주소입니다. 이 계정을 잃으면 관리자 화면에 들어갈 방법이 없습니다.

필요한 답
실제 운영 이메일 주소 1개 이상. 2명 이상을 권합니다 — 한 명이 자리를 비워도 운영이 멈추지 않습니다
주의
비밀번호는 각자 초대 메일에서 직접 설정합니다. 문서·메신저에 적지 마세요
03 CTA 정리 방향 — A · B · C 게이트 G1

기획서는 문의 CTA를 5곳으로 정했는데 실제로는 12종이 있습니다. 초과분 7종 중 2종은 문의 버튼이 아닌데 문의로 집계되는 오류고, 5종은 정상 작동하는 진짜 문의 버튼입니다.

먼저 읽기
별도 문서 「CTA 12종 정리안」 — 세 안의 대가까지 비교해 두었습니다
  • 안 A — 오류 2종만 고치고 기획서를 현행에 맞게 개정 (개발 추천)
  • 안 B — 기획서대로 7종 전부 제거. 플로팅 문의 바와 FAQ·빌더 문의가 사라집니다
  • 안 C — 오류 2종만 고치고 나머지는 보류. G1은 계속 미통과
04 모바일 성능 — 연출을 줄일까요, 기준을 조정할까요? 게이트 G4

게이트는 모바일 성능 85점을 요구하는데 홈이 미달입니다. 그런데 원인이 기획서가 요구한 것입니다 — 기획서 §6.1은 "전부 같은 방식으로 움직이면 AI로 한 번에 뽑은 티가 난다"며 섹션별로 다른 인터랙션을 요구했고, 바로 그 인터랙션이 점수를 깎습니다.

서버 응답이 늦던 문제(650ms)는 오늘 해결했습니다 — 서버를 미국에서 서울로 옮겨 50~76ms가 됐습니다. 남은 것은 순수하게 화면 연출의 무게입니다.

  • 안 A — 홈에 한해 기준을 낮춘다 (예: 홈 60 / 상세 85). 연출을 지킵니다
  • 안 B — 첫 화면 아래 섹션을 나중에 그린다. 스크롤 연동 애니메이션을 손봐야 합니다
  • 안 C — 히어로의 흐르는 블록 수를 줄인다. 무한 흐름 연출이 짧아집니다
먼저 할 일
최종 점수는 PageSpeed Insights로 다시 재야 합니다. 로컬 측정은 PC 부하에 따라 44~66까지 흔들립니다 — 회의 전에 제가 재서 정확한 숫자를 붙이겠습니다
05 조원 명단 (이름 · 이메일) 완성도

builders 에 빌더 10명이 있지만 전부 가짜 주소(@sample.invalid)라 아무도 로그인할 수 없습니다. 화면에는 이름이 보이는데 본인 글을 쓰거나 프로필을 고칠 수 없는 상태입니다.

지금 이 플랫폼은 "시연물"이지 "팀이 쓰는 도구"가 아닙니다. 명단 한 장이면 풀리는 항목이고, 승인도 클라이언트도 필요 없습니다.

필요한 것
참여 조원의 이름 · 이메일 목록. 초대 메일이 발송되고 각자 비밀번호를 설정합니다
덤
있으면 좋은 것 — 한 줄 소개, 주요 기술 스택. 없으면 나중에 각자 채우면 됩니다
06 범위 변경을 문서에 반영할까요? 문서 정합성

기획서는 화면 17개, 관리자 메뉴 4개로 확정했는데 실제로는 화면 20개, 관리자 메뉴 7개입니다. FAQ 관리 · 콘텐츠 관리 · 사이트 설정이 나중에 추가됐고, 이미 그대로 두기로 승인된 상태입니다.

기능은 문제가 없습니다. 다만 기획서에는 아직 "2차로 미룬다"고 적혀 있어, 나중에 인수인계할 때 "왜 문서와 다르냐"는 질문이 반드시 나옵니다.

  • 지금 반영 — 기획서·백로그를 현재 상태에 맞게 갱신 (권장)
  • 납품 시 일괄 — 변경 이력만 모아 두었다가 마지막에 한 번에

결정이 아니라 작업 — 반응형 육안 확인

게이트 G3(반응형 3종 깨짐 없음)이 코드로는 확인됐지만 눈으로는 아직입니다. CSS 구간과 마크업은 전부 확인했고 가로 스크롤도 0인데, 실제로 보이는 모습은 사람이 봐야 합니다.

방법
크롬에서 F12 → 기기 모드로 375 · 768 · 1024 폭에서 전 화면을 훑습니다
왜 제가 못 하나
자동화 도구가 브라우저 창을 978px 아래로 줄이지 못합니다. 375px 확인이 원천적으로 불가능합니다
걸리는 시간
20~30분. 누구든 한 명이면 됩니다

정리 — 회의에서 답할 것

  1. 저장소 비공개 전환할지
  2. 운영 관리자 이메일 (2개 이상 권장)
  3. CTA A · B · C
  4. 모바일 성능 A · B · C
  5. 조원 명단 이름 · 이메일
  6. 범위 문서화 지금 / 납품 시
  7. (작업) 반응형 육안 확인 담당자

1·2·5·6은 답만 주시면 그날 반영됩니다. 3·4는 고른 안에 따라 작업량이 다릅니다 — A·C는 화면이 안 바뀌어 재검수가 없고, B는 여러 화면이 바뀌어 반응형 재확인이 필요합니다.
