빌더 계정 운영

팀원 계정을 만들고, 권한을 정하고, 필요할 때 잠그는 방법입니다. 계정 발급은 관리자 화면에서 되고, 관리자 권한을 주는 것만 DB에서 합니다. 그 차이가 실수가 아니라 설계라는 점이 이 문서의 요점입니다.

대상 AI 빌더 그룹 관리자 플랫폼 읽는 사람 팀 내부 · 운영 관리자 작성 2026-08-17

지금 상태

관리자 화면에 들어갈 수 있는 계정은 builder@test.kr 하나뿐이고, 테스트용 주소입니다. 이 계정을 잃으면 관리자 화면에 들어갈 방법이 없습니다.

builders 목록에는 빌더 10명이 있지만 전부 가짜 주소(@sample.invalid)라 아무도 로그인할 수 없습니다. 화면에 이름만 있고 본인 글을 쓰거나 프로필을 고칠 수 없는 상태입니다. 조원 명단(이름·이메일)만 나오면 바로 실제 계정으로 바꿀 수 있습니다.

계정 발급 — 관리자 화면에서 됩니다

관리자 → 빌더 관리 → + 계정 발급

  1. 이름 · 이메일 · 슬러그 · 역할 라벨을 입력합니다

    슬러그는 공개 프로필 주소가 됩니다 (/builders/dohyun). 영문 소문자·숫자·하이픈만 씁니다. 역할 라벨은 표시용 문구일 뿐 권한과 무관합니다 — "플랫폼 · 어드민" 같은 소개말입니다.

  2. 발급 방식을 고릅니다

    임시 비밀번호 — 그 자리에서 비밀번호를 만들어 보여줍니다. 지금 기본값입니다.
    초대 링크 — 링크를 만들어 보여줍니다. 슬랙·문자 등 원하는 경로로 전달합니다.

  3. 화면에 뜬 값을 옮겨 적고 닫습니다

    ⚠ 임시 비밀번호와 초대 링크는 "지금 한 번만" 표시됩니다. 창을 닫으면 다시 볼 수 없습니다. 놓쳤다면 아래 §비밀번호 재설정으로 다시 만들면 됩니다.

  4. 본인이 첫 로그인 후 비밀번호를 바꿉니다

    임시 비밀번호로 발급된 계정은 로그인하면 비밀번호 변경 화면으로 넘어갑니다.

메일은 자동으로 가지 않습니다

지금은 링크·비밀번호를 화면에 보여주기만 합니다. 직접 전달하셔야 합니다.

이유 — Supabase 기본 메일은 인증 토큰을 주소의 # 뒤에 붙여 보내는데, # 뒤는 서버로 전달되지 않아 우리 쪽에서 읽을 수 없습니다. 커스텀 SMTP를 붙이면 초대 메일 방식으로 바꿀 수 있습니다.

빌더는 무엇을 할 수 있나

발급된 계정은 항상 일반 빌더입니다. 관리자가 아닙니다.

메뉴 · 동작빌더운영 관리자
Insight 관리 — 본인 글만 보임OO
Work 관리 — 본인이 참여한 프로젝트만OO
내 프로필 수정OO
발행 — 공개 사이트에 올리기XO
승인 요청 (작성 후 제출)OO
승인 대기 · 승인 · 반려XO
빌더 관리 (계정 발급 · 비활성화)XO
FAQ 관리 · 콘텐츠 관리 · 사이트 설정XO
남의 프로필 수정XO
배지 달기 (✳ 이달의 빌더)XO

빌더가 쓴 글은 바로 공개되지 않습니다. 작성 → 승인 요청 → 관리자 승인 → 발행 순서입니다. 한 번 승인 요청을 보낸 글은 관리자가 처리하기 전까지 빌더가 고칠 수 없습니다.

메뉴를 숨기는 것은 편의일 뿐입니다 — 주소를 직접 쳐도 서버에서 다시 막습니다. 빌더 계정으로 실제 접근을 시도해 차단을 확인해 두었습니다(릴리스 게이트 G7 통과).

관리자 권한 주기 — 화면에는 없습니다

일부러 막아 두었습니다. 버그가 아닙니다.

화면에도, 서버에도 역할을 바꾸는 경로가 없습니다. 기획서 §2.2가 "관리자 승격은 DB 직접 변경으로만" 이라고 정한 대로입니다.

이유 — 계정별 접근 제어는 행 단위라 "내 것이면 수정 가능"까지만 막습니다. 그래서 빌더가 우리 화면을 거치지 않고 자기 계정의 역할을 직접 admin으로 바꿀 수 있었습니다. DB에서 그 권한 자체를 회수해 경로를 닫았습니다.

올리는 방법

Supabase → SQL Editor 에서 실행합니다.

update public.builders
   set role = 'admin'
 where email = '올릴사람@주소';

되돌릴 때는 'builder' 로 바꿉니다. 본인 계정도 같은 방법으로 내릴 수 있으니 마지막 관리자를 내리지 않도록 주의하세요 — 그러면 아무도 못 들어옵니다.

관리자는 두 명 이상 두시기를 권합니다

한 명뿐이면 그 사람이 자리를 비우거나 계정을 잃는 순간 운영이 멈춥니다. 계정 발급 · 승인 · 사이트 설정이 전부 관리자 전용이라 대신할 사람이 없습니다.

그 밖에 할 수 있는 것

상황어떻게
비밀번호를 잊었다 빌더 관리 → 해당 줄 → 재설정 링크 발급. 본인이 로그인 화면의 "비밀번호를 잊으셨나요?"로 직접 요청해도 됩니다
임시 비밀번호를 놓쳤다 위와 같습니다. 재설정 링크를 새로 만들면 됩니다
퇴사·이탈로 접근을 막아야 한다 빌더 관리 → 비활성화. 로그인이 막히고, 공개 사이트의 참여 빌더 표시에 (비활성) 이 붙습니다. 계정과 글은 남으므로 되돌릴 수 있습니다
이메일을 바꿔야 한다 화면에서는 안 됩니다 — 이메일이 로그인 주체라 바꾸면 재인증이 필요합니다. 새 계정을 발급하는 편이 안전합니다

주의

⚠ 비밀번호와 링크를 단톡방에 올리지 마세요

  • 초대 링크와 재설정 링크는 비밀번호와 같습니다. 링크를 가진 사람이 곧 그 계정입니다
  • 단톡방·공용 채널은 나중에 들어온 사람도 지난 대화를 볼 수 있습니다. 1:1로 전달하세요
  • 전달한 뒤에는 본인에게 바로 비밀번호를 바꾸도록 안내하세요
  • Supabase의 Secret key(service_role)는 어떤 경우에도 공유하지 마세요. 이 키 하나면 모든 보안 정책을 우회해 DB 전체를 읽고 지울 수 있습니다

지금 필요한 것

  1. 조원 명단 (이름 · 이메일)

    지금 등록된 빌더 10명은 전부 가짜 주소라 아무도 로그인할 수 없습니다. 명단이 나오면 실제 계정으로 교체합니다.

  2. 운영 관리자로 쓸 실제 이메일 — 2개 이상

    현재 builder@test.kr 하나뿐이고 테스트 주소입니다. 정해지면 계정 발급 후 위 SQL로 올리고, 로그인과 권한까지 확인해 드립니다.

비밀번호는 각자 본인이 설정합니다. 문서나 메신저에 적어 보내실 필요가 없습니다.
